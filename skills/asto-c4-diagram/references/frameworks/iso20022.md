# ISO 20022 with C4

ISO 20022 is the messaging standard for payments between banks, clearing houses and payment systems. In a C4
diagram it belongs in the **technology of a relationship**, so the reader sees which messages cross each line.

## How to apply it

- Write the messages in the relationship `technology`: `"ISO 20022 pacs.008 / pacs.002"`. The script finds them
  (pattern `xxxx.nnn`), warns about unknown ones, and with `--doc` lists them with their names.
- Use it where messages are really exchanged in ISO 20022: interbank transfers, clearing houses, instant payment
  schemes, SWIFT, bank-to-customer statements. Customer-facing APIs (app → backend) are usually JSON/HTTPS:
  leave them as they are.
- **Local schemes may use their own versions or formats.** When you are not sure which messages a clearing house
  or payment system uses, propose the usual ones and add a `notes` entry such as "Confirm the ISO 20022 messages
  and versions required by <clearing house>".
- On a Dynamic diagram, show request and reply as separate numbered steps: `pacs.008` to the clearing house, then
  `pacs.002` back.

## Most used messages

| Message | Name | Typical use |
|---|---|---|
| pain.001 | Customer Credit Transfer Initiation | Customer or company asks its bank to pay |
| pain.002 | Customer Payment Status Report | Bank reports the status back to the customer |
| pain.008 | Customer Direct Debit Initiation | Creditor collects by direct debit |
| pain.013 | Creditor Payment Activation Request | Request to pay |
| pain.014 | Creditor Payment Activation Request Status Report | Answer to a request to pay |
| pacs.008 | FI To FI Customer Credit Transfer | Interbank transfer of a customer payment |
| pacs.002 | FI To FI Payment Status Report | Accepted / rejected status between institutions |
| pacs.004 | Payment Return | Returning a settled payment |
| pacs.009 | Financial Institution Credit Transfer | Bank-to-bank transfer (own account, cover) |
| pacs.028 | FI To FI Payment Status Request | Asking for the status of a payment |
| camt.052 | Bank To Customer Account Report | Intraday account report |
| camt.053 | Bank To Customer Statement | End-of-day statement |
| camt.054 | Bank To Customer Debit Credit Notification | Notice of a debit or credit |
| camt.056 | FI To FI Payment Cancellation Request | Asking to cancel or recall a payment |
| camt.029 | Resolution Of Investigation | Answer to a cancellation or investigation |
| acmt.023 | Identification Verification Request | Checking an account or alias before paying |
| acmt.024 | Identification Verification Report | Answer to the verification |
| admi.002 | Message Reject | A message could not be processed |
| head.001 | Business Application Header | Header that travels with the messages |
